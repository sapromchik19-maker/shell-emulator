# Эмулятор командной оболочки UNIX

Практическая работа №1 по дисциплине «Конфигурационное управление».

**Вариант №4**

## Описание проекта

Программа представляет собой эмулятор командной оболочки UNIX-подобной операционной системы с графическим интерфейсом.

Эмулятор разработан на языке Python с использованием стандартной библиотеки tkinter для создания графического интерфейса.

На данный момент реализованы первые два этапа практической работы: REPL и конфигурация.

## Этап 1. REPL

На первом этапе разработан графический интерфейс, позволяющий пользователю вводить команды и получать результаты их выполнения.

Реализованы следующие возможности:

- Отображение имени виртуальной файловой системы в заголовке окна.
- Ввод команд через графический интерфейс.
- Разбор команд и аргументов с учётом кавычек.
- Обработка неизвестных команд и неверных аргументов.
- Завершение работы программы через команду `exit`.

Поддерживаемые команды:

| Команда | Описание |
|---|---|
| `ls` | Заглушка, выводящая название команды и аргументы |
| `cd` | Заглушка, выводящая название команды и аргументы |
| `exit` | Завершение работы эмулятора |

На данном этапе команды `ls` и `cd` не выполняют реальных операций с файловой системой.

## Этап 2. Конфигурация

На втором этапе реализована возможность настройки эмулятора через параметры командной строки.

Поддерживаются параметры:

| Параметр | Описание |
|---|---|
| `--vfs` | Путь к физическому расположению виртуальной файловой системы |
| `--script` | Путь к стартовому скрипту с командами эмулятора |

При запуске значения переданных параметров выводятся в консоль для отладки.

### Выполнение стартового скрипта

Эмулятор поддерживает автоматическое выполнение команд из текстового файла.

Команды выполняются последовательно. В графическом интерфейсе отображаются введённые команды и результаты их выполнения.

При возникновении первой ошибки выполнение стартового скрипта прекращается. В окне выводится номер строки и сообщение об ошибке.

После остановки стартового скрипта графический интерфейс остаётся доступным для ручного ввода команд.

## Запуск программы

Для запуска необходим Python 3 с поддержкой tkinter.

Запуск без дополнительных параметров:

```bash
python src/shell_emulator.py
```

Запуск с указанием VFS:

```bash
python src/shell_emulator.py --vfs "example_vfs"
```

Запуск со стартовым скриптом:

```bash
python src/shell_emulator.py --script "scripts/start.txt"
```

Запуск с двумя параметрами:

```bash
python src/shell_emulator.py --vfs "example_vfs" --script "scripts/start.txt"
```

В Windows программу также можно запустить через файл `run.bat`.

## Примеры использования

Пример выполнения команды `ls`:

```text
virtual_fs:~$ ls documents
Команда: ls
Аргументы: ['documents']
```

Пример обработки аргументов в кавычках:

```text
virtual_fs:~$ cd "My Documents"
Команда: cd
Аргументы: ['My Documents']
```

Пример неизвестной команды:

```text
virtual_fs:~$ unknown
Ошибка: unknown: команда не найдена
```

Пример ошибки аргументов:

```text
virtual_fs:~$ ls file1 file2
Ошибка: ls: слишком много аргументов
```

## Этап 3. Виртуальная файловая система

На третьем этапе реализована загрузка виртуальной файловой системы (VFS) из директории на диске пользователя.

Для работы с виртуальной файловой системой создан класс `VirtualFileSystem` в файле `src/vfs.py`.

При загрузке программа считывает структуру каталогов и содержимое файлов в оперативную память. Информация о файлах хранится в словаре Python.

Ключами словаря являются относительные пути к элементам файловой системы. Значением для файла является его содержимое в байтовом виде, а для каталога используется `None`.

### Поддерживаемые команды

| Команда | Описание |
|---|---|
| `vfs-info` | Выводит имя загруженной VFS и SHA-256-хеш её данных |
| `vfs-init` | Сбрасывает рабочую VFS к пустому состоянию и очищает её физическое представление |

Команда `vfs-info` вычисляет SHA-256 на основе относительных путей, типов элементов и содержимого файлов. При повторном вызове без изменения данных результат хеширования остаётся одинаковым.

Команда `vfs-init` очищает виртуальную файловую систему в оперативной памяти и удаляет содержимое её физической директории.

В целях предотвращения случайного удаления пользовательских данных выполнение `vfs-init` ограничено непосредственными подкаталогами `vfs_work`.

### Тестовые виртуальные файловые системы

Для проверки работы программы подготовлены следующие варианты VFS:

- `vfs_examples/minimal` — минимальная файловая система.
- `vfs_examples/several_files` — файловая система с несколькими файлами.
- `vfs_examples/nested` — файловая система с тремя уровнями вложенных каталогов.

Для проверки сброса используются рабочие копии в каталоге `vfs_work`.

### Запуск с VFS

Пример запуска с минимальной файловой системой:

```powershell
python src/shell_emulator.py --vfs "vfs_examples/minimal"
```

Пример запуска с вложенной файловой системой:

```powershell
python src/shell_emulator.py --vfs "vfs_examples/nested"
```

Пример запуска стартового скрипта:

```powershell
python src/shell_emulator.py --vfs "vfs_examples/nested" --script "scripts/stage3_error.txt"
```

### Тестирование третьего этапа

Для проверки различных вариантов VFS созданы BAT-скрипты:

- `scripts_os/test_minimal.bat`
- `scripts_os/test_several.bat`
- `scripts_os/test_nested.bat`

Для проверки выполнения команд используются стартовые скрипты:

- `scripts/stage3_success.txt`
- `scripts/stage3_error.txt`

Первый скрипт проверяет успешное выполнение команд, второй — прекращение выполнения при возникновении ошибки.

### Автоматические тесты

Для автоматического тестирования используется стандартный модуль Python `unittest`.

Запуск всех тестов из корня проекта:

```powershell
python -m unittest discover -s tests -p "test_*.py" -v
```

Тесты проверяют загрузку различных VFS, обработку отсутствующей директории, формат SHA-256, повторяемость и изменение хеша, а также защиту исходной VFS от сброса.
### Особенности реализации VFS

Виртуальная файловая система загружается из директории, указанной пользователем при запуске программы. Содержимое файлов и структура каталогов сохраняются в оперативной памяти.

При загрузке выполняется проверка существования директории и типа файловых объектов. Символические ссылки не допускаются.

Для вычисления SHA-256 используются относительные пути, типы элементов и содержимое файлов. Перед добавлением пути и содержимого в хеш указывается их длина, что обеспечивает однозначное представление данных.

Команда `vfs-init` возвращает рабочую VFS к пустому состоянию. При этом очищается структура в оперативной памяти и удаляется содержимое соответствующей директории на диске.

Для предотвращения случайного удаления пользовательских данных команда `vfs-init` работает только с непосредственными подкаталогами `vfs_work`.

### Обработка ошибок

Программа обрабатывает следующие ситуации:

- Неизвестная команда.
- Неправильное количество аргументов.
- Незакрытые кавычки.
- Отсутствие директории VFS.
- Передача файла вместо директории VFS.
- Некорректные элементы файловой системы.
- Отсутствие стартового скрипта.
- Ошибка чтения стартового скрипта.
- Попытка сброса VFS за пределами разрешённой рабочей директории.

Дополнительное тестирование

Реализованы автоматические тесты загрузки файловой системы, вычисления SHA-256, проверки изменения хеша и сброса VFS.

Тесты также проверяют защиту исходных файлов от удаления.
